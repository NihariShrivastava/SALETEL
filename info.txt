====================================================================================================
1. EXECUTIVE SUMMARY & SYSTEM PURPOSE
====================================================================================================
SALETEL (formerly FieldSync) is an enterprise-grade, multi-role data collection platform, operational
auditing workstation, and CRM lead pipeline engine.

In large distributed field organizations (telecoms, insurance, utilities, sales, government surveying),
field agents capture vast amounts of unstructured data across different business verticals (domains).
SALETEL was engineered to solve three major industry bottlenecks:
1. Dynamic Customization: Business domains need custom forms without software developers writing new
   code or database migrations every time a field changes.
2. Real-Time Lead Pipeline: Field submissions must automatically flow through an operational hierarchy:
   Surveyors -> Counters -> Team Leads -> Telecallers -> File Handlers -> Managers -> Admins.
3. Multi-Tier SLA & Telecaller Accountability: Leads must be audited, call-logged, escalated based on
   configurable SLA thresholds (Hot, Warm, Cold), reassigned across agents, and exported into
   executive-level analytical reports and Excel workbooks.

- Purpose: Scalable PostgreSQL database with built-in PostgREST APIs, Row Level Security (RLS),

- Real Project Usage:
  * Singleton Client (src/lib/supabase.ts): Initialized using Vite environment variables:

  * Complex Relational Queries:
    - Inner and outer joins: supabase.from('submissions').select('*, surveyors!surveyor_id(*),
      domains(*), form_templates(name, fields)')
    - Array contains filtering: .contains('counter_ids', [user.id])
    - Soft delete filtering: .or('is_deleted.is.null,is_deleted.eq.false')
    - Parallel multi-query execution: Using Promise.all([query1, query2, query3]) to slash API
      waterfalls and deliver sub-300ms dashboard loads.
  * Client-Side Secure Hashing: Web Crypto API (crypto.subtle.digest('SHA-256', ...)) used for
    cryptographic password validation.

SALETEL implements a 7-tier Role-Based Access Control hierarchy:

====================================================================================================
3.1. ADMIN PORTAL (Path: /admin/*)
----------------------------------------------------------------------------------------------------
The control center of the entire enterprise.
Key Modules:
1. Dashboard Overview (/admin/dashboard):
   - Real-time KPI cards: Total Submissions, Active Surveyors, Total Team Leads, Total Telecallers.
   - Recharts Line Chart: Submissions trend over time.
   - Recharts Donut Chart: Distribution of submissions across operational domains.
   - Recent Submissions table with live status badges.
2. Domain Management (/admin/domains):
   - Create, edit, and soft-delete business verticals (e.g., Telecom, KYC, Solar, Insurance).
   - Domain-level configuration: custom icon selection, theme color picker, active template count.
   - Direct link to launch the Form Template Builder for that domain.
   - Trash bin view with soft-deleted domain and template recovery.
3. Form Template Builder (/admin/domains/:domainId/template):
   - Drag-and-drop builder using @dnd-kit.
   - Field Palette: Short answer, Paragraph, Number, Email, Phone, Dropdown, Multi-select, Radio,
     Checkbox, Yes/No, Date, Time, Datetime, File Upload, Signature, GPS Location, Rating.
   - Field Settings: Required toggle, placeholder, helper text, min/max length, regex validation,
     custom error messages, width (full/half/third), and conditional visibility rules.
   - Interactive Preview Modal: Test-fill the form in a simulated modal before publishing.
4. File Form Management & Builder (/admin/file-forms, /admin/file-forms/new):
   - Builds secondary custom documentation forms used specifically by File Handlers.
5. Role & User Management (/admin/surveyors):
   - Unified management interface for all human operators (Surveyors, Team Leads, Telecallers,
     File Handlers, Managers).
   - Assign user credentials (username, password).
   - Relational mapping: Assign which Domains, Form Templates, Counters, Team Leads, and
     Telecallers each user belongs to.
   - Subordinate assignment: Allows Team Leads and Telecallers to have dedicated pools of agents.
6. Counter Management (/admin/counters):
   - Configure physical retail counters/workstations and assign surveyors to them.
7. Submissions Auditing (/admin/submissions):
   - Master log of all field submissions.
   - Filter by Domain, Status (submitted, reviewed, approved, rejected, reverted), File Handler,
     or Date.
   - Detail inspection: View complete customer responses, inspect uploaded files, view GPS location,
     and add administrative review notes.
   - One-click workflow: Approve, Reject, or Revert submission back to the field.
8. Master Reports & Multi-Tab Analytics (/admin/reports):
   - 5 deep-dive analytical tabs:
     * Domain Breakdown: Submissions volume and percentages per domain.
     * Surveyor Productivity: Submissions count, performance metrics, and last-active tracking.
     * Telecaller CRM Performance: Assigned leads, call conversions, breakdown by lead status
       (New, Immediate, Hot, Warm, Cold, Skipped, Wrong Number, Closed, Reverted).
     * Team Lead Breakdown: Hierarchical view of Team Leads and their assigned telecallers.
     * File Handler Performance: Completed files, pending leads, turnaround efficiency.
   - Excel Export Engine: Instant generation of .xlsx spreadsheet files.
9. Lead Status Count (/admin/lead-status):
   - Global status aggregation counters with drilldown modal to view every lead in each status.
10. Assigned Leads Analysis & Reassignment (/admin/assigned-leads):
    - Multi-select lead reassignment across telecallers with real-time balance indicators.
11. Telecaller SLA Settings (/admin/settings):
    - Configurable SLA thresholds in days for Hot, Warm, and Cold leads.

4. COMPLETE RELATIONAL DATABASE SCHEMA & ENTITY MODELS (POSTGRESQL / SUPABASE)
====================================================================================================

The database is built on PostgreSQL inside Supabase, featuring 10 relational tables:

1. `admin_users`
   - id: UUID (Primary Key, default gen_random_uuid())
   - username: TEXT (Unique, case-insensitive)
   - password_hash: TEXT (SHA-256 client-hashed)
   - created_at: TIMESTAMPTZ

2. `domains`
   - id: UUID (Primary Key)
   - name: TEXT (Unique domain vertical name, e.g. "Telecom KYC")
   - description: TEXT
   - icon: TEXT (Lucide icon identifier)
   - color: TEXT (Hex color code)
   - is_deleted: BOOLEAN (Soft-delete flag)
   - created_at: TIMESTAMPTZ

3. `user_roles`
   - id: UUID (Primary Key)
   - name: TEXT ('Surveyor', 'Team Lead', 'Telecaller', 'File Handler', 'Manager')
   - description: TEXT

4. `counters`
   - id: UUID (Primary Key)
   - username: TEXT (Unique)
   - password_hash: TEXT
   - location: TEXT (Branch or desk location)
   - domain_id: UUID (Foreign Key -> domains.id)
   - created_at: TIMESTAMPTZ

5. `surveyors` (Master User Table for all operational staff)
   - id: UUID (Primary Key)
   - username: TEXT (Unique)
   - password_hash: TEXT
   - full_name: TEXT
   - phone: TEXT
   - email: TEXT
   - domain_id: UUID (Foreign Key -> domains.id)
   - user_role_id: UUID (Foreign Key -> user_roles.id)
   - assigned_domains: TEXT[] (Array of UUIDs for multi-domain access)
   - assigned_template_ids: TEXT[] (Array of assigned FormTemplate UUIDs)
   - counter_ids: TEXT[] (Array of assigned Counter UUIDs)
   - team_lead_ids: TEXT[] (Array of supervising Team Lead UUIDs)
   - telecaller_ids: TEXT[] (Array of assigned Telecaller UUIDs)
   - assigned_users: TEXT[] (Array of subordinate agent UUIDs)
   - assigned_file_template_id: UUID (For File Handlers)
   - location: TEXT
   - is_active: BOOLEAN (Account active / disabled toggle)
   - created_at: TIMESTAMPTZ

6. `form_templates` (Dynamic Form Definitions)
   - id: UUID (Primary Key)
   - domain_id: UUID (Foreign Key -> domains.id)
   - name: TEXT (Form title)
   - description: TEXT
   - fields: JSONB (Array of FieldConfig objects defining inputs, types, validation, rules)
   - is_active: BOOLEAN
   - version: INTEGER (Revision counter)
   - is_deleted: BOOLEAN (Soft delete)
   - created_by: UUID (Foreign Key -> admin_users.id)
   - created_at: TIMESTAMPTZ
   - updated_at: TIMESTAMPTZ

7. `file_form_templates` (Dynamic File Form Definitions)
   - id: UUID (Primary Key)
   - name: TEXT
   - description: TEXT
   - fields: JSONB
   - is_active: BOOLEAN
   - version: INTEGER
   - is_deleted: BOOLEAN
   - created_at: TIMESTAMPTZ
   - updated_at: TIMESTAMPTZ

8. `submissions` (Master Field Submissions & Leads)
   - id: UUID (Primary Key)
   - form_template_id: UUID (Foreign Key -> form_templates.id)
   - domain_id: UUID (Foreign Key -> domains.id)
   - surveyor_id: UUID (Foreign Key -> surveyors.id)
   - telecaller_id: UUID (Foreign Key -> surveyors.id, nullable)
   - data: JSONB (Key-value dictionary mapping field IDs to submitted user responses)
   - status: TEXT ('submitted' | 'reviewed' | 'approved' | 'rejected' | 'reverted')
   - lead_status: TEXT ('new' | 'cold' | 'warm' | 'hot' | 'immediate' | 'skipped' |
                        'wrong_number' | 'reverted_to_tl' | 'closed' | 'deleted')
   - lead_status_updated_at: TIMESTAMPTZ
   - telecaller_remark: TEXT
   - admin_notes: TEXT
   - location_lat: DOUBLE PRECISION (GPS Latitude)
   - location_lng: DOUBLE PRECISION (GPS Longitude)
   - device_info: TEXT
   - submitted_at: TIMESTAMPTZ
   - reviewed_at: TIMESTAMPTZ
   - reviewed_by: UUID

9. `file_submissions` (Secondary Verification Files)
   - id: UUID (Primary Key)
   - file_form_template_id: UUID (Foreign Key -> file_form_templates.id)

   - updated_at: TIMESTAMPTZ

    - previous_status: TEXT
    - new_status: TEXT
    - remarks: TEXT
    - created_at: TIMESTAMPTZ

6. KEY TECHNICAL INNOVATIONS & ARCHITECTURAL HIGHLIGHTS
====================================================================================================

6.1. Dynamic JSON Schema Form Builder & Renderer:
- Rather than hardcoding database columns for every question, forms are defined as a JSON array of
  FieldConfig objects stored in a PostgreSQL JSONB column.
- The custom FormFieldRender engine dynamically maps schema types to React components with validation,
  conditional rendering ('dependsOn' rules), and layout widths (full, half, third).

6.2. In-Memory Template Caching (templateCache):
- When rendering lead inspection tables or audit modals, repeatedly querying Supabase for template
  field schemas causes severe network lag and redundant SQL executions.
- An in-memory Map cache (`templateCache`) was engineered in ViewFormModal.tsx to cache template
  schemas across the browser session, slashing repeated network queries to zero.

6.3. SLA Auto-Triage & Stale Lead State Machine:
- Integrated with date-fns to compute elapsed time since 'lead_status_updated_at'.
- Automatically identifies leads flagged as "skipped" from previous days and updates their status back
  to "new" via a batch Supabase .in('id', staleSkippedIds) operation upon telecaller dashboard load.

6.4. Bulk Lead Reassignment:
- Enables Team Leads and Admins to select dozens of leads using checkboxes and transfer them to another
  telecaller in a single transactional batch query, balancing call loads instantly.

6.5. Multi-Workbook Real-Time Excel Report Exporter:
- Integrated SheetJS (xlsx) to convert arbitrary, nested JSONB data structures into standardized
  flat tabular rows, allowing administrators to generate comprehensive audit reports on demand.
